# 묵상 부분 연결 안내서

7단계 묵상 인도를 맡는 부분이다. Diary 쪽(main.py, 로그인, 저장, 조회, 챗봇, 화면)이 이 부분을 연결할 때 알아야 할 것을 적었다. 이 폴더 안의 코드는 들여다보지 않아도 된다.

## 연결

`main.py`에 두 줄을 넣는다.

```python
import meditation
app.include_router(meditation.router)
```

필요한 것은 환경변수 `ANTHROPIC_API_KEY`와 `bible/` 폴더(공통)다.

## 세 가지 일

모든 주소는 `/api/meditation` 아래에 있다. 오류는 `{"error": "묵상자에게 보여 줄 수 있는 문장"}`으로 돌려준다.

### 1. 묵상 시작: `POST /api/meditation/start`

보내는 것:

```json
{"ref": "골로새서 3:18-4:1"}
```

받는 것:

```json
{
  "session_id": "…",
  "book": "골로새서", "chapter_start": 3, "verse_start": 18,
  "chapter_end": 4, "verse_end": 1, "passage": "골로새서 3:18-4:1",
  "verses": [{"chapter": 3, "start": 18, "end": 18, "label": "18", "text": "…"}],
  "missing": []
}
```

- 본문은 한 단락이다. 30절 이내면 묵상자가 정한 범위를 그대로 받고, 그보다 긴 범위만 거른다. 장 경계를 넘을 수 있다.
- `verses`의 한 항목은 한 단위다. 원문에서 묶인 절은 `start`와 `end`가 다르고 `label`이 `"18-19"`처럼 나온다.
- 오류: 형식이 틀림, 30절 초과, 장의 끝을 넘음(400), 본문이 DB에 없음(404).

### 2. 대화 한 번: `POST /api/meditation/chat`

보내는 것:

```json
{"session_id": "…", "message": "묵상자의 글"}
```

받는 것:

```json
{"reply": "인도자의 다음 말", "completed": false}
```

- 시작 직후 첫 호출은 `message`를 `null`로 보낸다. 인도자가 먼저 말을 연다.
- 묵상이 끝나면 `completed`가 `true`가 된다. 그때 화면은 입력칸을 치우고 "오늘 묵상을 정리해 드릴까요?"라고 묻는다. 묵상자가 청하면 3번을 부른다.
- 끝났는지는 인도자에게 시키지 않고, 대화 밖에서 따로 확인한다(`prompts/meditation_finish.md`). 인도자의 지시문(`prompts/meditation_system.md`)에는 앱을 위한 요구를 넣지 않는다.
- 오류 502는 AI의 답을 받지 못한 것이다. 같은 글을 다시 보내면 된다. 기록에 중복으로 남지 않는다.

### 3. 묵상 완료 기록: `POST /api/meditation/record`

보내는 것:

```json
{"session_id": "…"}
```

받는 것: 묵상 완료 기록. 항목은 아래 15개이고 순서도 이대로다.

| 항목 | 자료형 | 내용 |
| --- | --- | --- |
| `book` | string | 묵상자가 정한 본문의 책 |
| `chapter_start` | integer | 시작 장 |
| `verse_start` | integer | 시작 절 |
| `chapter_end` | integer | 끝 장 (한 장 안이면 `chapter_start`와 같다) |
| `verse_end` | integer | 끝 절 |
| `passage` | string | 예: `골로새서 3:18-4:1` |
| `title` | string | 단락의 짧은 제목 (AI) |
| `prayer` | string | 시작 기도. 묵상자의 원문 (맞춤법과 띄어쓰기만 바로잡음) |
| `observation` | string | 묵상자의 관찰을 정리한 글 |
| `background` | string | 인도자가 제공한 배경 |
| `interpretation` | string | 묵상자의 해석을 정리한 글 |
| `truth` | string | 진리. 묵상자의 원문 (맞춤법과 띄어쓰기만 바로잡음) |
| `applied_truth` | string | 적용 진리. 찾은 진리 가운데 묵상자가 삶에 적용하기로 고른 하나. 묵상자의 원문 |
| `application` | string | 묵상자의 적용을 정리한 글 |
| `closing_prayer` | string | 마침기도. 묵상자의 원문 (맞춤법과 띄어쓰기만 바로잡음). 없으면 빈 글 |

- 글 항목은 여러 줄일 수 있다. 줄바꿈(`\n`)으로 나뉘고, 줄 앞에 `- `(목록)나 `1. `(번호)가 붙는다. 예: 관찰은 절마다 한 줄, 진리는 문장마다 한 줄.
- 이 부분은 기록을 **만들기만** 한다. 저장하지 않는다.
- `date`, `meditation_time`, `uid`는 들어 있지 않다. 저장하는 쪽이 저장할 때 넣는다.
- 본문 위치 여섯 항목은 묵상자가 처음 정한 본문에서 가져온다. AI가 대화를 보고 추정하지 않는다.
- `prayer`, `truth`, `closing_prayer`는 묵상자의 글이다. AI는 맞춤법과 띄어쓰기만 바로잡을 수 있고, 코드가 원문과 견주어 낱말이 달라졌으면 버리고 원문을 쓴다.
- 묵상자의 글이 아직 없을 때 부르면 409를 돌려준다.

## 오늘의 본문을 내어 주는 두 가지

묵상 중인 책이 있으면, 앱이 그 책에서 이어지는 본문을 끝 절까지 골라 내어 준다. 묵상자는 그대로 받거나, 다른 절을 눌러 끝을 바꾸거나, 함께 읽는 본문을 직접 적는다. 어디서 끝날지는 본문을 보기 전에는 알 수 없기 때문이다.

- `GET /api/meditation/following?book=에베소서&chapter=2&verse=3`: 그 책에서 2:3 다음에 이어지는 본문을 돌려준다. 장을 넘어 이어지고, 30절 안팎을 돌려준다. 책의 처음부터 보려면 `chapter=1&verse=0`.
  받는 것: `{"book": "에베소서", "verses": [...], "finished": false, "ends_book": false}`. `finished`가 `true`이면 그 책을 끝까지 묵상한 것이다.
- `GET /api/meditation/suggest?book=에베소서&chapter=2&verse=3`: 같은 본문에서 한 단락이 마무리되는 끝 절을 제안한다. 절 수 제한 없이, 펼쳐 본 범위 안에서 고른다.
  받는 것: `{"book": "에베소서", "chapter": 2, "end": 7}`. 제안하지 못하면 `chapter`와 `end`가 `null`이고, 그때는 묵상자가 직접 고른다. 제안 지침은 `prompts/meditation_suggest.md`에 있다.

모두에게 같은 단락표를 주지 않는다. 제안은 그때그때 하고, 정하는 것은 묵상자다. 한 책을 마치기 전에는 그 책에 머문다.

## 멈췄다가 이어서 하기

묵상을 중간에 멈추고 나중에 이어서 마칠 수 있다. 출근길에 시작한 묵상을 퇴근길에 마치는 경우다.

- 화면은 주고받을 때마다 대화를 기기에 보관한다. 묵상자가 따로 저장하지 않아도 된다.
- 다시 열면 달력의 오늘 칸 아래에서 이어서 할지 묻는다.
- `POST /api/meditation/resume`: 보관해 둔 대화를 받아 묵상을 되살린다. 서버가 그사이 꺼졌다 켜졌어도 된다.
  보내는 것: `{"ref": "에베소서 2:4-7", "messages": [{"role": "assistant", "content": "…"}, {"role": "user", "content": "…"}, …]}`. 인도자의 말로 시작해 인도자의 말로 끝나야 한다.
  받는 것: 묵상 시작과 같다 (`session_id`, 본문 위치, `verses`).
- 되살린 뒤 첫 호출은 `{"session_id": "…", "message": null, "resume": true}`로 보낸다. 인도자가 어디까지 했는지 짚고 멈춘 곳에서 이어 간다.
- 인도자의 지시문은 건드리지 않는다. 돌아왔다는 사실만 대화 안의 보이지 않는 신호로 알린다 (`signals.py`).
- 같은 기기에서만 이어진다. 기기를 바꿔 이어 가려면 대화를 서버에 저장해야 한다.
- 서버는 한동안 쓰지 않으면 쉬다가 깨어나면서 진행 중인 대화를 잊는다. 그때 대화 호출이 404를 돌려주면, 화면은 보관해 둔 대화로 `resume`을 부른 뒤 같은 호출을 다시 한다. 묵상자는 끊긴 것을 모른다.
- 대화 호출에 `expect`(화면이 알고 있는 지금까지의 대화 수)를 함께 보내면, 연결이 끊겨 같은 글이 두 번 와도 서버가 이미 받은 답을 그대로 돌려준다.

## 저장 전 확인

저장되는 것은 AI가 만든 기록이 아니라 **묵상자가 확인한 기록**이다.

1. 화면이 기록을 보여 주고 "이대로 저장할까요?"라고 묻는다.
2. 묵상자는 고칠 곳이 있으면 그 자리에서 직접 고친다. 본문 위치 여섯 항목은 고칠 수 없다.
3. 묵상자가 "저장해 주세요"를 누르면 화면이 확정된 기록을 `window.saveMeditationRecord(record)`에 넘긴다.

Diary 쪽은 화면에 이 함수 하나를 만들어 저장 API를 부르면 된다. 함수가 끝나면 화면은 "저장했습니다"를 보여 주고, 오류를 던지면 그 문구를 보여 준다. 화면은 그와 함께 기록을 이 기기의 브라우저에도 보관해 달력에 보여 준다. 일기장(DB)이 연결되기 전까지의 임시 보관이다.

```javascript
window.saveMeditationRecord = async (record) => {
  // record: 위의 15개 항목. 여기서 저장 API를 부른다. uid, date, meditation_time은 백엔드가 넣는다.
};
```

## 화면이 지켜야 할 규칙

인도자의 말(`reply`) 안에는 본문을 가리키는 표시가 들어 있다. 화면은 이 표시를 그 자리에서 성경 DB의 본문으로 바꿔 보여 주어야 한다. 인도자는 본문을 직접 옮겨 적지 않는다. AI가 옮겨 적다 틀리는 일을 막기 위해서다.

| 표시 | 화면에 보여 줄 것 |
| --- | --- |
| `[[본문]]` | 본문 전체 (`verses` 모두) |
| `[[3:18]]` | 3장 18절을 포함하는 단위 하나 |
| `[[6:18-19]]` | 6장 18절을 포함하는 단위 하나 (묶인 단위) |

인도자의 말에는 `**굵은 글씨**`, 번호 목록(`1.`), 점 목록(`-`)이 들어 있을 수 있다. 화면은 이것도 모양대로 보여 준다.

`frontend/index.html`이 이 규칙을 구현한 참고용 화면이다.

## 알아 둘 것

- 진행 중인 대화는 서버 메모리에 `session_id`로 보관한다. 서버를 끄면 사라진다. 묵상 부분은 사용자를 구분하지 않으므로, 로그인한 사용자와 `session_id`를 묶는 일은 Diary 쪽이 맡는다.
- 묵상 부분은 `bible/`을 읽기만 하고, `diary/`와 `chat/`을 알지 못한다.
- 7단계와 원칙은 `prompts/meditation_system.md`에, 기록 정리 지침은 `prompts/meditation_record.md`에, 끝을 확인하는 물음은 `prompts/meditation_finish.md`에 있다.
- `prompts/meditation_system.md`는 짧게 둔다. 인도자는 귀납적 성경 묵상을 이미 알고 있고, 지시를 덧붙일수록 인도가 굳어진다.
- 이 모델은 답하기 전에 생각하는 기능이 켜져 있고 그 분량이 답의 한도에 함께 계산된다. 답이 끊기면 `AI_MAX_TOKENS`를 올린다.
